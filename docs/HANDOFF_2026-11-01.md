## Work done this session
### 1. Wrestler texture bug (ISS-130) — still open, main priority
- Symptom: wrestlers' skin/lighting wrong in entrances and matches (PCSX2 correct). PCSX2 draws correct skin from the same texture slots where ours holds stale apron data with a noise CLUT.
- Facts established: game saves VRAM regions with sceGsExecStoreImage (CT32, sbw 4) to RAM and restores them every frame (ours as 16x16 tiles to dbp 15296, PCSX2 as bulk stripes). Region 15296..16319 holds textures (T8 at 15616 256x256, 15872, 16064, 16136, 16000) and CLUTs (16272..16300). T8/T4 uploaded as CT32 raw swizzled data. CT16S scratch pass draws into FRAME fbp 15296 fbw1 psm10 (present in both).
- Ruled out: lighting, T8-as-CT32 transfer format, queued DMA/GIF before StoreImage (drain added in GS.cpp, no change), readback addressing, a missing CT16S pass.
- Theory (strongest): ordering/timing/content of the saved buffer, or the skin upload, differs in ours (skin never uploaded, or uploaded before the save, or the per-frame restore overwrites it).
- Probes in code: `[vramw]` (gs_frontend.cpp, widened 13300-16400), `[savedump]` (gs_vulkan_bridge.cpp; writes `analysis\live\save_%02d_%x_%ux%u_seq%llu.bin`), `[norestore]` (flag bit 20; drops host-to-local transfers to dbp 15296 rw=16 rh 16/64), `[evtrd]` (CD.cpp), `[atanwatch]` (svr06_overrides.cpp). Remove all before shipping.
- NEXT STEP: at an entrance run `svrlive raw 'vramdump; gifcap 12000'` (must be one command so the pre-state is replayed; wait for the count), then `flag 20 1` and check whether skin appears. Compare `vramw.txt` upload seq against `vramw_save.txt` save seq; decode `save_*.bin` as VRAM (see `analysis_tmp/saved_bufs.png`).
- The user also reports the Locker Room is very glitchy graphically and entrances run slowly (possible per-frame readback stalls and probes). Likely the same cause; unmeasured.
- Planned: the user will play every wrestler's entrance in PCSX2; build a capture routine (pcsx2cap.py `grab` copies eeMemory/vu1Memory/Scratchpad from the newest SLES-53676 savestate; `ingest` produces per-dump dirs). Needs the user's PCSX2 hotkeys for "Save Single Frame GS Dump" and save state.

### 2. Unlock All / Infinite money cheats (ISS-131) — implemented, needs verification
- Save buffer (profile) is at RAM 0x3D9BF8, 901,288 bytes. Roster records 0xA0 bytes at 0x3D9C26.
- Shop item table in RAM: stride 0x28 from 0x591FF8 (index 0). Words: [0]=id, [1],[2]=ids, [4]=flag, [6]=category, [7]=buyable, [8]=price (28000 for Legends), [9]=owned. Static; SOLD state is NOT in the table. Poking price to 0 (`svrlive poke 592090 0`) lets you buy with $0 cash.
- Purchases write bits in the save buffer: four 0x12-byte bitmaps at save offsets +0x6A38C (S0), +0x6A39E (S1, mirror of S0), +0x6A3B0 (S2) and +0x6A3C2 (S3). S0 and S1 get bit n set for table index n (Andre=3, Bret Hart=4, Mankind=5 gave 0x38). S2/S3 got one bit (0x20 at byte 9) after the second purchase; meaning unknown. +0x6A384 is a dirty counter (1 after purchase, 0 after save).
- Verified by user: with the first cheat build, Legends unlocked and were selectable; The Rock and Austin stayed locked ("behind other unlockables"), and normal shop items were not purchasable.
- Implementation: `Kernel/Stubs/SvrConsole.cpp`, in `svr06_console_poll()` after the button-sequence block, every 4 frames. Settings keys `cheat.unlockAll`, `cheat.money` (ps2settings). UI: `ps2_runtime.cpp` F1 raylib overlay, tab "Cheats" (also a copy in ps2_debug_panel.cpp Settings tab). Backups: `*.bak_cheats`.
- Latest edit (built in the final build of this session): the unlock now covers all table entries with category 1-9 including non-buyable ones, forces buyable=1 and owned=0 for index >= 3, and zeroes price when money cheat is on. Unverified.
- Cash is NOT mapped: "Infinite money" just makes every shop price $0; the on-screen Cash stays 0. The PSP CWCheat for this game sets max money to 99,999,999 (0x05F5E0FF) as a u32, so the PS2 cash is probably a u32 in the save buffer. Find it with `fillz` bisection over the save buffer while watching the Shop's "Your Cash" number (restore with `unfillz`), then add a `cheat.money` write of 99999999.
- PCSX2 equivalent still to do: a .pnach for SLES-53676 that sets the same save-buffer bytes (CodeBreaker/AR codes found online are NTSC-U or encrypted AR MAX PAL arena modifiers, not usable directly).
- Open question: Rock/Austin unlock conditions may live elsewhere (another bitmap or match-count flags); if the latest cheat does not unlock them, diff the save buffer around achieving the prerequisite.
